# Report card images and printing

The report preview has a Print button beside Map missing fields. It requests a fresh, authorized snapshot for the selected learner, including temporary LRN inputs, and opens a fullscreen spreadsheet print setup. The paper preview is on the left; sheet selection, orientation, Fit to page / Fit to width, margins, and Fit to screen zoom are on the right. Print report card opens the system printer dialog using those settings. Fit to width is capped by the available paper height so each complete report area stays on one page, including its footer. Printing does not save grades or create storage objects. Visible worksheets use saved Excel Print Areas, or the actual content, borders and image bounds when none are set. Empty formatting beyond the report is ignored. Each area is fitted and centered within the margins on the selected A4 or short bond paper (Letter, 8.5 x 11 inches). A4, Fit to width, and quarter-inch margins are the defaults; hidden sheets and the mapping controls are excluded. Oversized workbooks are rejected rather than silently printing only the preview window.

Embedded PNG, JPEG and GIF pictures are read from internal DrawingML relationships and rendered at their one-cell, two-cell or absolute anchors. External images are never fetched. Image data is bounded to 4 MB and 40 pictures per sheet. Basic ellipse and rectangle DrawingML shapes, including text placeholders, are rendered as inert generated SVG. Charts, VML, other vector images and advanced picture effects are not rendered; the Excel download preserves those original parts. Workbook notes explain preview limitations.

Generated reports keep the original fonts, borders, number formats and dimensions. The explicit formatting exception is horizontal and vertical centering of mapped period grades, final grades and final averages. Cloned styles restrict this alignment change to grade cells; labels and remarks retain their original alignment. The preview uses each imported cell's font and explicit workbook dimensions; the app font is limited to controls. Print cells retain the template font family, size, bold, italic and underline styling. Fonts must be available on the device. Package validation checks unmodified parts and the exact expected style changes.


Verification: parser/image safety tests, generated workbook alignment and preservation tests, preview/download tests, UI tests, and the synthetic production browser regression in `tests/report-card-generation-browser.mjs` (includes a print PDF artifact).

The preview and final printer document share one renderer. Unwrapped text spills across empty adjacent cells, separately from cell borders. Borders use shared vector lines to avoid doubled edges.
