# TeacherCo PWA + install experience — Batch 2

## What changed

The public landing page now has a secondary, device-aware install action in its hero. Request Early Access remains the primary action for visitors. Existing signed-in destinations are passed through from the landing page's shared access-policy helper.

- Android/desktop Chromium: a captured `beforeinstallprompt` event enables Install TeacherCo. Only clicking the button calls `prompt()`. The event is single-use, including dismissal. Acceptance shows an installation-requested message; `appinstalled` confirms installation in that browser session.
- iPhone/iPad: Install TeacherCo opens a native accessible dialog explaining Share → Add to Home Screen → Add, with Open as Web App guidance when offered. Escape, the close button, and the backdrop dismiss it; focus returns to the install button.
- Standalone: `display-mode: standalone` and iOS `navigator.standalone` show Open TeacherCo. No persistent installed flag or new cookies are used. Separate browser sessions are not assumed to be installed.
- Unsupported/no-JavaScript: Continue in browser remains a normal link. The original login and early-access actions still work.
- Installed/app links use the supplied account destination or `/login` for anonymous visitors. Pending, active, onboarding, verification, and suspension routing are unchanged.

## Worker and privacy

Serwist remains the only worker framework; Webpack scripts and automatic worker registration remain intact.

- Precache is limited to four small app icons and `/offline.html`. Large landing illustrations and application chunks are not downloaded en masse during worker installation.
- Runtime CacheFirst is restricted to named public brand/icons, immutable Next JS/CSS/font assets, and Next Image requests whose source is an explicitly public TeacherCo image. Cache is bounded to 64 entries and 30 days.
- All other GET requests use NetworkOnly: HTML navigations, RSC, APIs, auth/admin endpoints, Supabase, signed file responses, and other external resources. Non-GET requests are not added to a cache.
- Authorization-bearing fetches bypass even the public precache route. Private/no-store responses, redirects, errors, and HTML cannot be written by the runtime asset strategy.
- Activation deletes legacy caches from the previous broad default Serwist rules. It does not delete Dexie/IndexedDB or pending sync work.
- Route prefetch caching is explicitly disabled. Returning online does not automatically reload a form and risk losing its inputs.
- Only failed document navigations receive the offline fallback; failed API requests remain failed requests, not HTML disguised as API data.

No classroom offline-sync functionality is introduced. A previously loaded screen shows an offline status when connectivity is lost; new offline navigations show the public fallback. Try again reloads the original requested URL and runs normal access checks after reconnection. A first-ever visit while already offline cannot load a worker that has never been installed.

## Local and production acceptance

No new environment variable, dependency, cookie system, database table, or migration is required. Deploy using the existing Vercel workflow; this task has not deployed the changes.

Local PWA testing uses a production server (the worker is intentionally disabled in `npm run dev`):

```sh
npm run build
npm run start -- --port 3000
```

For automated browser checks, start production on port 3100 and run `node tests/pwa-browser.mjs` and `node tests/landing-browser.mjs`. `LANDING_TEST_URL` can override the address.

After deployment to **https://teacherco.vercel.app**:

1. In Chrome/Edge, open the landing page over HTTPS. DevTools → Application should show the manifest, icons, and one active worker at `/sw.js` with scope `/`.
2. When the browser offers installation, click the secondary Install TeacherCo button. Confirm the browser prompt. The browser controls eligibility; if it does not emit an event, Continue in browser remains available and its own menu may still offer installation.
3. Open the installed app from the device launcher. Confirm its icon, brand theme, standalone window, and `/today` startup. Logged-out users reach login; pending users reach invite; suspended users reach suspended; active users reach onboarding or Today as appropriate.
4. On iPhone/iPad, click Install TeacherCo. Follow Share → Add to Home Screen, keep Open as Web App enabled if shown, and tap Add. Use Safari if the option is unavailable in the current browser.
5. With the worker activated, go offline and navigate to a protected route. Confirm the branded offline page. Reconnect and click Try again; confirm normal access checks resume.
6. With a test teacher account, visit classroom/report pages, log out, then go offline and revisit their URLs. There must be no private page/API entries in Cache Storage. Test suspension similarly; offline fallback must not reveal the prior account's cached server responses.
