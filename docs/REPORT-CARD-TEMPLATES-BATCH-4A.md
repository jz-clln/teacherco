# TeacherCo Batch 4A handoff

Implemented October 5, 2026. Entry point: **Settings → Academic tools → Report card templates**. This batch stores blank account-level workbooks and provides a read-only coordinate viewer.

## Requested handoff

1. **Migration:** `supabase/migrations/0018_report_card_templates.sql`. Applied alone to verified project `qsmyzajvkpkdsmwezwfa`; only 0018 was added to the migration ledger. Earlier migrations were not replayed or reconciled.
2. **Schema:** `report_card_templates` stores UUID identity, teacher owner, editable name/status, original display filename, canonical source path, MIME, byte size, SHA-256, sheet count, structural metadata and timestamps. There are owner/status and active owner/hash indexes. No cell values are stored in metadata.
3. **Bucket:** private `report-card-templates`, 10 MiB bucket limit, XLSX/octet-stream MIME allowance.
4. **Storage policies:** authenticated owners can read/delete their own prefix; insert requires an owner UUID prefix and fresh template source path with no registered metadata. A restrictive policy denies updates, including overwrite/move. The existing restrictive active-access policy applies to the new bucket. The insert subquery explicitly compares `t.storage_path` to `storage.objects.name`.
5. **RLS:** owner-only table policy plus restrictive verified, active account access. Other teachers and other administrators cannot read owned templates. Pending, suspended, unverified and anonymous users are denied.
6. **Grants:** authenticated SELECT/INSERT/DELETE and UPDATE only for name/status; anonymous/public grants revoked. Service-role access exists for administration and test setup only; ordinary feature actions use the cookie-authenticated client.
7. **Immutable fields:** trigger rejects changing identity, owner, path, filename, bytes/hash, MIME, sheet structure and creation timestamp. Only name, status and automatic updated timestamp can change. Storage UPDATE is denied, and removing a registered object does not authorize recreating it at that path.
8. **Size limit:** 10 MiB (10 × 1024 × 1024 bytes), displayed as 10 MB. Client gate, bucket configuration, actual downloaded size check and parser guard enforce it.
9. **File validation:** client hints provide early feedback; the server reads the uploaded bytes and validates independently. Extension must be `.xlsx`; empty/oversized files and incompatible MIME types fail. `.xls`, `.xlsm`, CSV, ODS, PDF and Word files fail.
10. **OpenXML validation:** lazy ZIP central-directory inspection, safe paths, duplicate entry detection, encrypted ZIP/OLE rejection, macro/ActiveX rejection, bounded decompression and strict XML namespace/root parsing. Required package relationships/content types/workbook/worksheet parts must parse. DTDs/entities, overlapping merges, invalid addresses and unsafe complexity fail closed. Parseable workbook/worksheet editing protection is accepted without removing or modifying it; the preview displays only a generic protection notice, never password hashes/verifiers or protection attributes. Encrypted Office containers and encrypted ZIP entries remain rejected. No XML or relationship target is fetched over the network.
11. **SHA-256:** Node `createHash('sha256')` over the exact server-downloaded bytes. Client hashes and sizes are ignored for registration.
12. **Original bytes:** source bytes are never passed through an Excel writer. Browser smoke compares the original hash after upload, viewing, rename, archive/reactivation and original download. Source reads also verify the stored size and hash.
13. **Upload pipeline:** server creates a UUID/canonical path → browser uploads once through authenticated Storage with `upsert:false` → server downloads, validates, parses and hashes → metadata inserted → viewer opens. A ref lock and disabled controls stop double-click submits; retries reuse the request identity. Direct Storage transfer avoids routing the 10 MiB body through a Vercel function. Vercel documents a [4.5 MB function payload limit](https://vercel.com/docs/functions/limitations).
14. **Partial failures:** validation/insertion/duplicate failures attempt removal only of the current unregistered owner path. Saved or uncertain metadata blocks cancellation cleanup. Uncertain saves retain the file for an idempotent retry; cleanup failure is reported. Cancellation does not navigate away when cleanup cannot be confirmed. Storage and SQL are not one transaction: abrupt tab closure or network loss can leave an unregistered private object; there is no scheduled orphan sweeper in this batch.
15. **Duplicate hashes:** one active template per owner/hash, enforced in SQL as well as the action. A duplicate displays the existing name and a View existing template link; the temporary duplicate file is removed. Archived copies may coexist; reactivation fails if an identical active copy exists. Optional simultaneous active copies are not enabled.
16. **Routes:** `/report-cards/templates`, `/report-cards/templates/new`, `/report-cards/templates/[templateId]`, and authenticated `/api/report-card-templates/[templateId]/download`. Route loading/error boundaries provide retry feedback.
17. **Components:** `TemplateUploadForm`, `TemplateManagement`, `TemplateViewer`, reusable `WorkbookGrid`, and the list/detail/upload route components. Existing buttons, confirmation dialog, colors, groups and shell are reused.
18. **List:** separate active/archived groups; name, original filename, file size, upload date and worksheet count; empty state and upload action. Listing reads structural metadata, not the workbook. Long names wrap.
19. **Upload UI:** blank-template guidance, name/file controls, `.xlsx` acceptance, validation errors, preparation/upload/validation progress and disabled repeated submissions. No filled learner report card is requested.
20. **Viewer:** server-produced bounded sheet windows rendered as a read-only HTML table with real coordinate headers, sheet chooser, address jump, row/column paging, warnings and a cell inspector. Workbook cells remain text, never editable inputs.
21. **Parsing location:** server-only ZIP/SAX/style/parser modules. The browser receives one safe preview window; it does not receive the full XLSX except through explicit original download. Each preview request rechecks ownership, access and byte hash. No unbounded shared server cache is introduced.
22. **Preview model:** sheet summary, window origin, bounded row/column dimensions and hidden flags, cell address/type/display text/sanitized styles/formula/cache, intersecting merge rectangles and warnings. Cell/formula text is bounded to 500 characters; response cap is 2 MiB. Persistent metadata contains structural sheet summaries only.
23. **Sheet order:** exact workbook names and index order retained. No Front/Back/SF9 name assumptions.
24. **Hidden sheets:** visible, hidden and veryHidden states retained and labeled; hidden sheets can be explicitly inspected. Hidden rows/columns are shown with a dot and explanatory label instead of silently losing their coordinates.
25. **Coordinates:** Excel base-26 column conversion and A1 validation through XFD1048576; actual row numbers survive window changes. Address jumps outside the bounded preview fail clearly. `CellSelection` emits only sheet name, master address and optional merged range.
26. **Merged cells:** one control per merged rectangle, row/column spans clipped to the current window, original master/range retained. Clicking C8:F8 selects C8 and displays C8:F8. Overlapping merges are rejected. No duplicate overlapping cell controls.
27. **Styles:** basic bold/italic/underline, bounded font size, sanitized colors/theme tint, solid fills, horizontal/vertical alignment, wrapping, safe borders and approximate numeric/percentage/currency/date formatting. Excel font families and unsupported advanced formatting are omitted. Freeze-pane presence is noted; the preview freezes its coordinate headers rather than reproducing Excel panes.
28. **Formulas:** never calculated. Formula text and safe cached display results appear in the inspector; missing cache is shown as unavailable. Shared formulas without an explicit expression are identified accordingly.
29. **External references:** detected where exposed by workbook relationships/formula syntax, with a warning. No external workbook is opened or fetched.
30. **Hyperlinks/XSS:** hyperlink labels and rich text are flattened to plain React text. No workbook-provided anchor, HTML injection, JavaScript URL or external-image request is rendered. Styles accept sanitized numeric/enum/hex fields only.
31. **Images/logos:** may be omitted with a warning; original bytes retain them. No image conversion or base64 image payload is sent to the viewer.
32. **Shapes/charts:** omitted with a warning. Non-worksheet sheet types retain their name/order/state and show an unsupported-preview message. At least one worksheet is required.
33. **Large sheets:** used extent bounded to 2,000 rows × 128 columns, window 60 × 24 cells. Sparse far-away cells mark the sheet truncated rather than expanding millions of DOM nodes. Maximum 20 sheets, 100,000 parsed cells and rows across a workbook, 100,000 shared strings, 1,000 merges per sheet, 2,048 ZIP entries, 50 MiB declared expanded size, 16 MiB per entry and 8 MiB per parsed XML part. XML depth/node limits and style collection limits also apply. Safely parsed material outside the preview bounds remains in the original file.
34. **Mobile:** sheet viewport scrolls horizontally/vertically within a bounded container; page itself does not overflow. App controls use the established 44px minimum. Grid cells retain spreadsheet-scale hit areas. Native buttons support keyboard activation; cell selection is temporary and resets on sheet/window changes. No global navigation item was added.
35. **Rename:** changes only trimmed display name; original filename/path/hash/layout remain unchanged. Names need not be globally unique.
36. **Archive/reactivate:** confirmation dialog, metadata status change only, preserved source and viewer/download availability. Duplicate-active constraint applies on reactivation.
37. **Download:** cookie-authenticated handler rechecks active access/ownership and verifies source hash, then redirects to a 60-second signed original URL. Response is private/no-store. Uploads use cacheControl 0; server verification reads use fresh cache nonces. Previously issued signed links remain bearer links for their validity period; already downloaded bytes cannot be revoked. Supabase documents [private downloads and cacheNonce](https://supabase.com/docs/reference/javascript/file-buckets-download) and [CDN caching behavior](https://supabase.com/docs/guides/storage/cdn/smart-cdn).
38. **Delete/cleanup:** confirms before deleting trusted source then metadata; storage failure retains metadata, metadata failure reports that the source was removed and asks for retry. Repeated missing-row delete is safe. Settings delete-all now includes this bucket/table and its confirmation copy names templates. Class deletion and remove-original-upload controls do not delete account templates. Future mapping references will need dependency checks before source deletion.
39. **Account level:** confirmed; owner is the authenticated teacher.
40. **Section binding:** none, no Section foreign key or assignment UI.
41. **Mapping:** none, no mapping persistence/table or inferred field meanings. Selection is component state only.
42. **Generation:** none; no report-card output, Excel filling, PDF/ZIP export or reportcardhistory changes.
43. **SF9:** no hardcoded layout, names, term/quarter structure or coordinates.

## Adaptive columns, merged outlines and Poppins ? October 8, 2026

Supersedes the earlier viewer typography and wide-sheet fallback: all UI previews keep the worksheet's detected columns (within the existing 128-column safety bound), including AX. Long sheets paginate rows instead of reverting to A?X. If a response exceeds 2 MiB, the server reduces the row count while retaining all columns; next/previous row navigation follows the actual returned window. Non-UI parser calls keep their previous default window.

Merged-cell perimeter segments are read from each edge cell, including subordinate cells, and drawn at their original row/column proportions. Border colors, widths and supported dash/double styles are preserved; automatic border color defaults to black. Workbook bytes, security validation and read-only behavior remain unchanged.

Poppins now applies throughout the application, including worksheet text, coordinates, codes and form controls. Regular and italic font variants are loaded through the existing Next font integration. This intentionally overrides source font families in the preview only; original workbook fonts are preserved in the stored/downloaded file. Different font metrics can change text wrapping compared with Excel.

Validation: 633 automated tests passed, one skipped; typecheck, lint and production build passed. Added fixtures cover AX across 300 rows, reduced row windows and borders stored on merged subordinate cells with unchanged SHA-256.

Production browser regression passed at seven viewport widths, including AX300 navigation, computed Poppins fonts, merged border elements, protected-source hash preservation and native/fallback full screen. Mobile zoom controls reserve space for the sheet; selecting 100% resets zoom on compact screens. Temporary accounts and workbook fixtures were cleaned up.
