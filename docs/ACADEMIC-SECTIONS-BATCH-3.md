# TeacherCo Batch 3 — Section Grade Book

Implemented and validated October 5, 2026. Open **Classes → Sections → a Section → Grades**. Changes are uncommitted and have not been pushed or deployed to Vercel.

## Implementation report

1. **Migration:** Added `supabase/migrations/0017_section_gradebook.sql`. Existing migrations were preserved. The full 0001–0017 chain and a populated 0016→0017 upgrade pass locally. The upgrade comparison includes existing Sections, memberships, classes, learners, assessments, confirmed scores, printed term grades, attendance, reports, timestamps and class revision values.
2. **Tables:** `section_grade_periods`, `section_subjects`, and `section_grade_entries`. No report-card, template, event-history, organization or collaboration tables were added.
3. **Constraints and indexes:** Stable UUID identities; unique period key and position per Section; positions 1–8; nonblank bounded labels; local subject ordering; a unique learner/subject/period cell; numeric grades from 0 to 100; composite Section/teacher, subject/Section/teacher, period/Section/teacher, membership/teacher and source-class/teacher relationships. Position uniqueness is deferred so reordering can be atomic. Grade lookup, learner and non-null source-class indexes support the main reads and relationships. Grade-bearing subjects/periods cannot be deleted because their entries reference them.
4. **RLS and grants:** All three tables have owner policies plus restrictive `has_active_access()` policies. Anonymous access is revoked. Pending, unverified, suspended and other-owner access is denied; an admin profile does not bypass ownership. Authenticated users have SELECT/INSERT/UPDATE; only configuration tables permit DELETE, with archived-Section restrictions and entry FKs. Grade entries have no ordinary DELETE grant. Both RPCs are `SECURITY INVOKER`, explicitly authenticate and check active ownership, and are granted to authenticated users only. Ordinary application operations never use service-role credentials.
5. **Period model:** UUID identity and a stable generic `period_*` key, separate from editable label and persisted position. No quarter/term-specific grade columns. This implementation supports up to eight total periods, including inactive periods.
6. **Presets:** Four quarters, three terms, two semesters, and custom. Three terms is the initial convenience choice, consistent with existing class records; teachers explicitly choose their Section structure.
7. **Custom periods:** Teachers can name, add, remove unused periods, reorder with Up/Down, and reactivate/make periods inactive. Renaming or reordering keeps grades attached to the original UUID. The UI prevents removal when entries exist, and database FKs enforce that rule. Setup writes check expected versions to prevent stale configuration replacement.
8. **Subject model:** Subjects are local to one Section and have name, optional code/category, order and active/inactive status. They have no permanent dependency on a TeacherCo class or global catalog. Duplicate names are representable with distinct UUIDs.
9. **Manual subjects:** Add and edit arbitrary names/code/category, reorder with accessible controls, and make inactive/reactivate. Duplicate names require an explicit acknowledgement before setup saves. An adviser-only Section can maintain subjects and grades without any linked classes.
10. **Add subjects from classes:** Teachers select linked classes and review the resulting subject list before saving setup. Class `subject` labels become independent Section subjects; existing matching labels are disabled to prevent automatic duplicate additions. Adding subjects does not import grades. Intentional duplicate-name subjects can be created manually with acknowledgement.
11. **Grade entries:** One authoritative current numeric value per Section/learner/subject/period. Null/no entry means missing; zero is a real grade. A deliberate clear stores null with manual provenance. Identity columns are immutable. New writes require active membership, subject, period and Section.
12. **Provenance:** `manual`, `teacherco_class`, or reserved `external_import`. Manual corrections clear class provenance. Class copies store source class ID, a bounded class/subject reference and a small snapshot containing source term, printed/calculated choice, original grade and class sync revision. No learner records or assessment dumps are stored in provenance. Standard created/updated timestamps are retained. Source-class deletion sets only its nullable ID to null and preserves the copied grade/reference/snapshot.
13. **Manual workflow:** Select subject and period → Enter grades → edit learner rows → Review & save → confirmation → atomic save. Blank and zero remain distinct. Decimal entry is supported; Enter advances to the next learner. Existing values and provenance are visible while editing. There is no per-keystroke autosave.
14. **Bulk transaction:** `save_section_grades` accepts up to 500 changed learners and applies all changes or none. It validates access, active relationships, source linkage, grade range, duplicate learner IDs and expected cell timestamps. A stale edit is rejected. The unique cell constraint, immediate client submit locks, disabled/pending controls and version checks prevent double-submit duplicates and stale retries. A lost-response retry may ask for refresh instead of replaying a write. `save_section_gradebook_setup` atomically updates periods/subjects and checks configuration versions.
15. **Class import:** Select destination subject/period, linked class, source class term and grade source. Review current, printed and calculated grades with add/change/unchanged/missing/outside-roster statuses. Confirm selected changes. Preview performs no writes; confirmation recomputes the preview server-side and checks its digest. The RPC checks class revision/linkage again under a row lock. No automatic class-to-Grade-Book synchronization exists.
16. **Source resolution:** Existing `getClassTermGrades` and `computeTermGrade` are reused. Printed grades come from `teacher_term_grades`; calculated values use the same class grading configuration, confirmed scores and deterministic helper as the class term-grade screen. The teacher explicitly chooses printed or calculated; differing values are shown together with a warning. No precedence is invented. Incomplete/missing calculated values cannot erase reviewed grades. Shared reads now paginate rosters, assessments and printed grades, fail on grading-read errors, and reuse the already-loaded configuration rather than making a redundant potentially inconsistent read. Formulas and class term structure were not changed.
17. **Manual-value protection:** Import keeps manual cells by default. Each differing manual value requires an explicit replacement checkbox. The final confirmation gives the selected change count, existing-value count and manual-replacement count. The RPC independently rejects unconfirmed manual replacement. Equal values retain their existing provenance and timestamp.
18. **Learner matching:** Exact learner UUID only. Duplicate display names do not match. Class learners outside the active Section roster appear in the preview but cannot be imported or automatically enrolled. A separate Manage Section roster link is provided.
19. **Archived/inactive behavior:** Archived Sections are readable and cannot accept normal Grade Book edits. Inactive learners retain grades and are excluded from ordinary bulk entry. A history toggle includes inactive learners, subjects and periods. Source-class unlink/delete preserves copied values, including in archived Sections. Intentional Section deletion still cascades its Grade Book; the existing typed-name confirmation now explicitly names reviewed grades and recommends archive for preservation. Learner profiles/classes remain independent.
20. **UI:** `/sections/[sectionId]/grades`, linked by a Section-level Grades tab. No new global navigation item. Uses the existing warm, flat design system, grouped surfaces, restrained rows, native confirmation dialog and explicit loading/error states. One subject is shown at a time, with grade completeness by period and unobtrusive provenance/date labels. After saving, a refresh state prevents briefly presenting old reviewed values as the new result.
21. **Mobile:** Learner rows show period/value pairs; desktop uses an actual table. Controls use the existing 44px minimum target sizing. Four Section tabs fit at 320px, and the five mobile destinations remain unchanged. No glass, blur, gradients or decorative spreadsheet imitation was introduced.
22. **Report-card templates:** None implemented.
23. **Excel-cell mappings:** None stored or implemented. External spreadsheet/paste import UI is explicitly deferred; `external_import` is reserved in the schema, not presented as a working importer.
24. **SF9 assumptions:** None in the Grade Book schema or UI. Flexible period data is separate from any future report-card layout.
25. **Learner identifiers:** No LRN, student-number or learner-reference-number fields were added.
26. **AI:** No AI determines, chooses or adjusts Grade Book grades.
27. **Class Record Sync and other features:** Class Record Sync code/history and What Changed were not modified. Grade Book operations do not update class scores, attendance, grading config, printed grades, sync revision or sync versions. Remote class snapshots verified this. Reports and Ask remain class-scoped; the small shared query-read improvements do not make either consume Section grades. Check and attendance behavior remain unchanged.

## Reproducing the browser smoke

Build the app and run the production server on local port 3327. In PowerShell, set `GRADEBOOK_TEST_PROJECT_REF` to the independently verified configured project reference, then run `node tests/section-gradebook-browser.mjs`. The script requires the existing local Supabase environment configuration, verifies both configured/linked project identity, restricts the browser URL to localhost, and removes its temporary accounts in `finally`. Admin credentials are used only for isolated fixture creation/cleanup; application actions and security assertions use ordinary authenticated clients. Do not print environment files or tokens.
